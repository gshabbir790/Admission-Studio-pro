# Admission Studio Pro

Offline-first Flutter migration of `admission-photo-camera.html`.
Package: `com.gshabbir.photostudio` · App name: **Admission Studio Pro**

All 7 phases from the original spec are implemented. See `ARCHITECTURE.md` for
the full feature inventory, HTML→Flutter migration map, and dependency list.

## Setup

This delivery is the Dart (`lib/`, `test/`) layer plus a hand-authored
`android/` host project. Because it wasn't generated by `flutter create`,
some platform scaffolding (launcher icon PNGs, `ios/` if needed,
`.metadata`) is intentionally not included — generate it once, then this
code drops in on top:

```bash
# One-time: scaffold any missing platform files without overwriting what's here
flutter create --platforms=android .

flutter pub get
dart run build_runner build --delete-conflicting-outputs   # Hive adapters
flutter test
flutter run
```

### Font assets
The bundled UI font is Inter. Arabic/Urdu student names use Flutter's platform
font fallback so the project does not fail to build when an optional Nastaliq
font asset is absent. If a specific institutional Nastaliq typeface is required,
bundle it locally and register it explicitly before release.

### Launcher icon
`AndroidManifest.xml` references `@mipmap/ic_launcher`, generated by the
`flutter create` step above using Flutter's default icon. Replace via the
`flutter_launcher_icons` package or Android Studio's Image Asset tool with
the real Admission Studio Pro mark before shipping.

## Release build

```bash
flutter build apk --release
flutter build appbundle --release
```

### Release signing
`android/app/build.gradle` currently points `release` at the debug
signing config so the build runs out of the box for local testing/QA.
**Before Play Store submission:**
1. Generate an upload keystore: `keytool -genkey -v -keystore upload-keystore.jks -keyalg RSA -keysize 2048 -validity 10000 -alias upload`
2. Create `android/key.properties` (never commit it) with `storePassword`, `keyPassword`, `keyAlias`, `storeFile`.
3. Replace the `release { signingConfig }` block in `android/app/build.gradle` with a `signingConfigs.release` built from `key.properties`.

## Phase-by-phase summary

**Phase 1 — Architecture & Storage.** Clean Architecture + MVVM folder
structure, Riverpod, Hive-backed `PhotoItem`/`PhotoSession` models, debounced
autosave/resume repository (`SessionRepository`, 900ms debounce, mirrors the
HTML's IndexedDB logic exactly). *Design choice: Hive instead of the spec's
"recommended" Isar — same offline guarantee, no codegen/native build step.*

**Phase 2 — Camera + Capture.** `CameraService` provides front/rear
switching, live preview, still capture, and a soft-fail camera fallback.
Capture is intentionally manual in this build; live face detection/auto-capture
is not advertised as implemented.

**Phase 3 — Image Editor + Segmentation + Resize.** `ImageAdjustmentsService`
(CSS-filter-equivalent brightness/contrast + 3×3 unsharp mask),
`ResizeService` (face-aware crop, never distorts, progressive-halving
downscale), `CaptionService` (Urdu-correct via `TextPainter`, composited onto
`package:image` buffers), `SegmentationService` (ML Kit Selfie Segmentation,
0.5/0.75 soft-edge confidence blend), `PhotoEditorScreen`.
*Design choice: non-destructive editing — original file untouched, edit
params stored on `PhotoItem` and applied once at export time, unlike the
HTML's destructive baking.*
*Language: app default switched to English (chooser/camera/naming/settings/
grid UI chrome); student names and printed captions still render Urdu/Arabic
correctly since that's user data.*

**Phase 4 — Grid + Session Management.** `PhotoGridScreen` (now the app's
root screen) with fixed-capacity grid, "+20 more", per-card edit/retake/
delete/rename, all wired through `SessionNotifier` so any mutation both
autosaves and invalidates that photo's processed-export cache.

**Phase 5 — Export pipeline.** `ImageProcessingService` orchestrates
resize → adjust → segment → caption → compress per photo (exact port of the
HTML's `processBtn` handler, including the same file-size binary-search
compression). `ZipExportService`, `PrintSheetService` (A4 @300 DPI, 4×5 grid,
name below photo, auto-paginated), `PdfExportService`, all
wired through `ExportController` with a live progress dialog and a
post-process export-actions sheet + paged A4 preview screen.

**Phase 6 — Android native integration.** Hand-authored `android/` host
project: `AndroidManifest.xml` (camera + scoped photos permissions,
FileProvider for sharing, ML Kit model-provisioning meta-data, no INTERNET
permission — genuinely offline), Gradle files (`applicationId
com.gshabbir.photostudio`, minSdk 23 for ML Kit headroom), ProGuard keep
rules for ML Kit/CameraX/pdf reflection targets, `PermissionService` wired
into the camera and gallery entry points (requested just-in-time, not at
launch).

**Phase 7 — Testing.** 9 test files: `FacePositionEvaluator` (7 threshold/
boundary cases), `ResizeService` crop math (center-crop, face-centered crop,
never-distorts, bounds-clamping), `ImageAdjustmentsService` pixel math,
`FilenameUtils` sanitization + collision-safe naming, `CompressionService`
size-budget adherence, A4 dimension constants, `PhotoItem`/`PhotoSession`
model round-trips and capacity growth.

## Known gaps / next steps if you keep going
- **ARB localization**: English is hard-coded in the UI layer right now;
  Urdu strings exist (`face_hint_strings.dart`) but aren't wired through
  `flutter_localizations`/`.arb` files yet for a real locale switch.
- **Widget/integration tests**: current tests cover services and pure logic;
  no widget-level or `integration_test` coverage yet (spec §42 asks for both).
- **API surface risk**: `google_mlkit_selfie_segmentation`'s `SegmentationMask`
  field names are implemented per its documented pattern — worth a quick
  diff against the exact installed version during `flutter pub get`, since
  ML Kit plugins occasionally rename mask accessors between minor versions.
- **App icon**: needs a real launcher icon asset (see "Launcher icon" above).
- **iOS**: this delivery targets Android only, per the original spec's
  "Android-first" / "Android production developer" framing.
